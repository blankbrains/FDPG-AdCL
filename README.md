# FDPG-AdCL: Adversarial Contrastive Learning with Dynamic Frequency-Patch Graphs for Point-Level Multivariate Time-Series Anomaly Detection

Implementation of FDPG-AdCL for point-level multivariate time-series anomaly detection. The pipeline integrates adversarial contrastive representation learning, global and local scoring, frequency-patch graph scoring, and score fusion.

Supported datasets: **MSL, SMAP, SMD, SWaT, and PSM**. Dataset-specific parameter settings are provided in `configs/`.

## Requirements

- Linux with Python 3.10.
- For GPU execution: an NVIDIA GPU and a driver compatible with the CUDA 11.8 PyTorch build.
- Python dependencies pinned in requirements.txt.

From the extracted FDPG-AdCL directory:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -B run_pipeline.py --help
```

The pipeline defaults to CUDA. Use --device cpu for CPU execution; full training may be slow.

## Dataset layout

Pass the directory of the individual dataset to --data-root.

| Dataset | Required layout |
| --- | --- |
| MSL / SMAP | train/*.npy, test/*.npy, labeled_anomalies.csv |
| SMD | train/, test/, test_label/ with matching .txt or .csv entity files |
| PSM | train.csv, test.csv, test_label.csv |
| SWaT | swat_train.csv and swat_test.csv; supported alternative names are listed in src/data/loading.py |

SWaT input must be CSV, not an Excel workbook. Its test file must contain a supported attack-label column. Keep sensor order and chronological order consistent. Channel counts must match the dataset configuration. Obtain datasets from their providers under the applicable access terms.

## Data protocol

Each entity's input training and test arrays are concatenated in their supplied chronological order, then partitioned as follows:

| Partition | Interval for a sequence of length N |
| --- | --- |
| Training region | [0, floor(N / 2)) |
| Validation | [floor(N / 2), floor(3N / 5)) |
| Test | [floor(3N / 5), N) |

The chronological ratio is **5:1:4**. Preprocessing and model fitting use the original normal training data within the training region. Validation data calibrate scores and thresholds. The test interval is continuous, and the partition boundaries are independent of the random seed.

## Run

Assuming PSM is stored at /data/PSM, preview the stages first:

```bash
python -B run_pipeline.py \
  --dataset psm --data-root /data/PSM \
  --output ./outputs/psm_seed42 --device cuda --seed 42 --dry-run
```

Dry-run checks configuration and entity discovery, then prints commands. It does not load all data, create run outputs or start training.

Run the full pipeline by omitting --dry-run:

```bash
python -B run_pipeline.py \
  --dataset psm --data-root /data/PSM \
  --output ./outputs/psm_seed42 --device cuda --seed 42
```

For a single SMD entity:

```bash
python -B run_pipeline.py \
  --dataset smd --data-root /data/SMD --entity machine-1-1.txt \
  --output ./outputs/smd_m11_seed42 --device cuda --seed 42
```

For MSL, SMAP and SMD, omit --entity to process all supported entity files in train/. Run each dataset separately using msl, smap, smd, swat or psm.

Model checkpoints are generated during training; pretrained weights are not included. Use checkpoints generated by this pipeline.

The output directory must not already exist. Before training, the runner checks data loading, channel counts and block lengths. Each stage writes a log; completed artifacts are retained on failure. The runner does not automatically resume partial runs. Use a new output directory for a fresh run.

--config selects a custom dataset YAML. The runner overrides data_root and seed explicitly. configs/branches.yaml contains only the RGCSF and FPLIR branch settings. Each invocation runs one seed.

## Files and outputs

```text
FDPG-AdCL/
├── README.md
├── requirements.txt
├── run_pipeline.py
├── configs/
│   ├── branches.yaml
│   └── five dataset YAML files
└── src/
    ├── data/
    ├── models/
    ├── losses/
    ├── training/      global encoder and local-model training
    ├── scoring/       shared, global and local score functions
    ├── graph/         frequency-patch graph fitting and scoring
    └── evaluation/    checkpoint derivation, inference, fusion and metrics
```

src/evaluation/aggregate_results.py provides score loading and entity aggregation. src/evaluation/evaluate_threshold_channel_diagnostic.py implements the final fusion and evaluation used by the runner. These modules are runtime dependencies.

Each run produces checkpoints/, global/, local/, base/, graph/, final/, logs/ and run_state.json. The final dataset report is final/datasets/<dataset>_metrics.json. run_state.json records resolved configurations, commands, completed stages and errors.

## Configuration and repeated runs

The five dataset files in [configs/](configs/) specify the local score weights, encoder warmup settings, and per-channel stem width. Each file also defines the base-fusion, graph, and boundary-fusion settings that `run_pipeline.py` reads from its `paper_pipeline` section. MSL uses an encoder FFT segment length of 16. Use the unified entry point to apply all of these values; individual stage CLIs retain their generic defaults unless explicitly overridden. Each invocation performs one seed; run three distinct seeds into separate output directories and average the resulting per-dataset metrics to obtain a three-run mean.

Stage modules use package imports. Run individual stages from the repository root with module syntax, for example:

```bash
python -B -m src.training.adcl_pretext --help
python -B -m src.graph.derive_frequency_patch_graph_scores --help
python -B -m src.evaluation.evaluate_threshold_channel_diagnostic --help
```
The recommended entry remains run_pipeline.py, which applies all dataset-specific manuscript settings.
